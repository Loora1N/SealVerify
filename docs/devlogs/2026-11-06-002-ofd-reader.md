## 目标与范围

将原本仅有帮助入口的工具扩展为可启动的本地 OFD 阅读器，支持完整多页阅读和常用导航。签章业务解析与密码验证继续使用独立的后续阶段，不把阅读成功视为验签结论。

PR #2 已由维护者于 2026-11-06 合并，任务基于 `bba03f4` 创建 `codex/ofd-reader`。路线由 M2 拆分为 M2a 阅读、M2b 签章结构与页面关联，验证流程调整为先打开阅读，再接入签章定位及验证材料。

## 关键决策

- Python 标准库提供本地启动和固定资源服务，浏览器执行 OFDRW 0.1.7 阅读组件；无需用户安装 Node.js，运行期间不使用 CDN。
- 依据 GB/T 33190—2016 的格式标准信息及 OFDRW 官方 API 集成；本次不实现密码运算或新增密码标准条款判断。
- 文档选择在浏览器内处理；命令行文件通过回环连接原样传递。原件不修改，没有远程上传或任意文件读取接口。
- 使用随包附带的 Noto Sans CJK SC，保留 OFL 授权与来源哈希，避免缺省中文字体导致空白文字。
- 多 DocBody 包在内存中选取阅读入口，原文件不变；关闭导出副本与验签，避免混淆阅读数据与签名证据。
- 修复固定版本上游在任务取消时误报模板加载失败的问题：构建时在处理模板结果前先检查取消，正常失败仍然报告；补丁位置改变时构建失败。
- 用户页码显示使用阅读组件自己的导航栏；宿主状态栏显示打开状态和总页数，避免多处页码不同步。

## 已知限制与未完成项

- 加密 OFD 不支持，特殊扩展、罕见图像编码与字体兼容性仍依赖引擎；未宣称通过完整格式符合性认证。
- 无原字体时使用备用字体，字形可能与原稿不同；扫描页面不提供 OCR。
- 单文件及解压、画布预算有限额；多文档内存阅读副本的解压上限为 128 MiB，具体见阅读器说明。
- 未执行物理打印机、所有浏览器/操作系统及真实业务文件验收。
- 签章属性关联、真实验签、证书验证和无需 Python 的独立安装包尚未实现。
