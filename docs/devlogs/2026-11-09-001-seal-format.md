## 目标与范围

依据 GB/T 38540—2020 第 6.1、6.3 a) 节，独立检查内嵌印章和 OFD 外置印章，任何错误记录后继续其他独立检查。增加独立 SESeal DER 的命令行检查；通用工具覆盖不足与输入文件问题分开展示。本轮不实现制章签名运算、制章者证书信任/吊销、印章有效期或内外置资源一致性。

版本为 0.5.0，分支 `codex/seal-format`。创建分支时 `origin/main` 为 `fe5e5b4`，随后快进纳入第一步的 `8ee6a9b`；该第一步 PR #5 尚未合并，因此本次 PR 明确依赖它，未代为合并或改写历史。

## 关键决策

- 按标准把第 6.3 a) 格式检查与 b)–d) 密码/证书/有效期检查分开；工具以诊断方式保留失败并继续独立检查。
- 第一阶段保留 SES_Signature、TBS_Sign、内嵌字段类型及版本一致性；原内嵌印章详细检查移到第二步，不重复堆叠明细。原属性解析契约不变，格式检查 ID 迁移见 [印章格式说明](../seal-format.md)。
- `checked_status` 表达已列出的检查，`coverage` 表达尚未覆盖的完整约束。通用 `referenced_profiles` 不再生成固定文件问题；完整符合性不足仍使 `overall_status` 为 `incomplete`，不提升为完整通过。
- 图像使用 Pillow 有界解码；宽高的毫米单位不与像素比较。SVG 只读安全 XML 根结构，不渲染、不访问外部资源。未知类型、超限或未覆盖语义记无法确定，实际可证明的损坏/不匹配记失败。
- Pillow 范围 `>=11.3,<14` 由 pip 选择与解释器兼容的版本。本机 Python 3.12.9 实际安装 13.0.0；Python 3.9 安装运行由当前提交 CI 验证，不把本机测试当作多版本验证。

## 已知限制与未完成项

- 完整 GB/T 20518、33560、35276 配置约束，厂商扩展、登记名称、图像文件规范及业务语义尚未全部实现。SVG 根结构可读仍需复核；栅格可解码也不是完整图像格式认证。
- 未执行密码验签、证书信任/吊销/用途有效性、授权匹配、当前有效期判断及内外置资源相等性。
- 图像限额为 4 MiB、单帧 400 万像素、16 帧、累计 1600 万像素；印章/证书/列表/检查明细沿用有界诊断，超限明确报告。
- 当前正常样例的完整格式状态仍为 `incomplete`，格式 CLI 返回 1；应结合已检查项结果判断，不能把所有非零码都理解成发现格式错误。
- 本机运行根目录 editable 环境，没有把 wheel 重新安装在本机运行；构建内容已核对，安装后测试由当前 CI 执行。
